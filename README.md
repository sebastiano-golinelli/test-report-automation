# Test report automation: from PDF lab reports to a checked Excel summary

A Python tool that reads tensile-test reports in PDF from different laboratories, normalizes units and
formats, checks every value, compares each specimen with its material specification and writes an
Excel report with a summary, all results, a list of issues to review and a chart.

AI is used only where fixed rules cannot work (reports written in free text), and every AI-extracted
value is checked against the document: if the number is not literally in the report, it is discarded
and the field goes to manual review. **The tool flags what it cannot read instead of guessing.**

> All reports in `samples/` are synthetic, generated by `samples/generate_samples.py`. The same pipeline
> applies to invoices, purchase orders, datasheets or any other document with values to extract.

## What it handles

| Lab | Format | How it is read |
|---|---|---|
| Lab Alpha | key-value lines, MPa, ISO dates | rules |
| Beta Testing Services | table, **ksi** and **US dates** (converted) | rules |
| Gamma Metrology | free text written by a technician | optional AI step, otherwise manual review |

Problems planted in the samples, all caught:

| Specimen | Problem | Result |
|---|---|---|
| AL-003 | elongation 6.5 % below the 8 % minimum | FAIL |
| ST-103 | elongation left blank by the lab | REVIEW |
| TI-202 | yield higher than tensile strength (transcription error) | REVIEW |
| ST-101 | same specimen in two reports (resubmitted) | REVIEW |
| AL-005, ST-104, TI-203 | values only in prose | REVIEW (or read by the AI step, with evidence) |

## Output

`output/test_summary.xlsx` with these sheets:

- **Summary**: per material, specimens passed, mean and minimum values against the specification minimums
- **Results**: every specimen with status (PASS / FAIL / REVIEW) and reason, how it was read, source file
- **Needs review**: one line per issue, ready to send back to the lab
- **AI evidence** (when the AI step runs): the exact quote each AI value was taken from
- **Chart**: yield versus tensile strength per material

## Run it

```bash
python -m venv .venv
.venv\Scripts\activate                 # Windows (on Linux/macOS: source .venv/bin/activate)
pip install -r requirements.txt
python samples/generate_samples.py     # create the sample PDFs (already included)
python -m reportbot samples/pdfs -o output/test_summary.xlsx
pytest                                 # 15 tests
```

Optional AI step for free-text reports (needs an Anthropic API key in `ANTHROPIC_API_KEY`):

```bash
python -m reportbot samples/pdfs -o output/test_summary.xlsx --ai
```

The AI step sends only the text of the free-text reports to the Claude API (model `claude-opus-5-5`,
structured output validated with Pydantic). Use it only with documents you are allowed to send to an
external service.

## How the AI step is kept honest

1. The model must return, for every value, the exact words of the report it took it from.
2. The quote must appear in the report and must contain the number: otherwise the value is discarded.
3. Values that survive still go through the same checks as the rule-based ones (completeness,
   physics, duplicates, specification).

The tests use a fake client to verify that an invented value is rejected.

## Structure

```
reportbot/extract.py    PDF reading and the rule-based parsers, one per lab format
reportbot/ai.py         optional Claude extraction with evidence checks
reportbot/validate.py   completeness, physical consistency, duplicates, specification
reportbot/specs.py      material minimums (indicative values, check the applicable standard)
reportbot/report.py     Excel report (openpyxl)
samples/                synthetic PDF reports and their ground truth
tests/                  pytest suite
```

## Limits

Text-based PDFs only (scanned images would need OCR first). Material minimums are indicative values from
common standards: check the standard, product form and thickness that apply to a real job.
